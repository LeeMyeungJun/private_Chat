# 모음 채팅 Android

Android Studio에서 이 `android/` 폴더를 Open하면 됩니다. Java 17, Android SDK 36, Gradle 8.13 / AGP 8.13.2를 사용합니다. Android 8.0 이상에서 설치할 수 있습니다.

## 사용

1. MainPC의 `모음 서버.lnk`로 서버를 실행합니다. PC에서도 대화하려면 별도 `모음 채팅.lnk`를 엽니다.
2. 서버 관리창의 **Android 앱 입장 가능** 상태를 확인합니다.
3. 휴대폰 앱에서 **서버 입장**을 누릅니다. 주소를 입력하거나 Tailscale에 로그인할 필요가 없습니다.
4. 닉네임만 입력하면 입장합니다. 비밀번호는 없습니다. MainPC와 같은 방·메시지·파일을 사용합니다.

APK는 [GitHub 최신 릴리스](https://github.com/LeeMyeungJun/private_Chat/releases/latest)의 `moeum-chat-*.apk` 파일을 설치합니다. 서버 처음 설치, 서버 프로그램에서 공지 보내기, 다른 프로그램의 알림 API 사용은 [저장소 README](../README.md)에 있습니다.

서버가 닫혔거나 접속되지 않으면 입장 화면에 안내가 표시됩니다. 채팅 중에는 10초마다 실제 서버를 확인합니다. 서버를 재시작하면 이전 방의 내용이 삭제되며 앱에서 다시 서버 입장을 누르면 새 주소를 찾습니다.

앱 첫 화면에는 입장 버튼 하나만 있습니다. 채팅 화면은 Figma `q8Oqf80owMxEvdV1afHKh9`, `3004:385`의 배경·색상·첨부/전송 리소스를 적용한 WebView로, 기존 실시간 채팅을 그대로 연결합니다. 사진 촬영/파일 선택과 저장 위치를 선택하는 다운로드를 지원합니다. Android 시스템 WebView 업데이트를 권장합니다.

## 주소 자동 발견

MainPC가 검증한 Quick Tunnel 주소와 실행별 UUID만 GitHub 저장소의 별도 `connection` 브랜치에 등록합니다. 채팅·첨부·세션 토큰은 등록하지 않습니다. MainPC에는 Git과 기존 저장소 쓰기 인증이 필요하고, 휴대폰은 GitHub 인증이 필요하지 않습니다. 작업 브랜치와 스테이징 영역은 바꾸지 않습니다. 등록 실패 시 관리창에 표시하고 60초마다 재시도합니다.

앱은 GitHub의 현재 연결 정보와 HTTPS `/api/health`의 UUID가 모두 일치할 때만 입장합니다. 종료 후 남은 주소는 서버 확인에서 거부됩니다. GitHub 공개 API 호출 제한 또는 네트워크 차단이 있으면 주소 확인이 실패할 수 있습니다.

다른 PC에서도 같은 저장소의 쓰기 인증으로 서버를 실행할 수 있습니다. 여러 서버가 켜져 있으면 마지막으로 주소를 등록한 서버가 새 입장 대상입니다. 이미 입장한 기기는 기존 서버에 계속 연결되며, 마지막 서버가 닫혀도 다른 서버를 자동 선택하지는 않습니다.

## 모바일 알림 울리기

채팅의 종 모양 버튼을 누르면 연결된 채팅 서버가 Firebase Cloud Messaging으로 앱에 호출 알림을 발송합니다. PC와 모바일 클라이언트는 서버에 요청만 보냅니다. 서버 관리창이나 다른 프로그램의 `POST /api/notifications`로 공지를 보내면 채팅에는 제목과 자세한 내용을 게시하고, 모바일에는 제목과 최대 160개 Unicode 문자의 요약을 보냅니다. 별도 Cloud Functions, 유료 서버, 데이터베이스는 사용하지 않습니다. 앱이 백그라운드에 있어도 알림을 받을 수 있고, 알림을 누르면 채팅 화면을 열거나 서버 입장을 시도합니다.

Firebase Android 구성 파일을 `app/google-services.json`에 두고 빌드합니다. 서버의 발송 인증 파일은 `.data/firebase-service-account.json`에 둡니다. 두 파일은 Git에서 제외됩니다. 앱의 Google 서비스 구성만 APK에 포함하고, 서버의 비공개 키는 APK에 포함하지 않습니다. 다른 PC로 서버를 옮기면 해당 PC에도 발송 인증 파일을 설정해야 합니다.

앱을 한 번 열고 Android 알림 권한을 허용해야 합니다. 알림 소리·진동은 휴대폰의 알림 채널과 무음/방해금지 설정을 따릅니다. 반복 호출은 서버 전체에서 15초 간격으로 제한합니다. Firebase 연결이 준비되지 않은 서버에서는 호출 버튼이 비활성화됩니다.

입장한 뒤에는 Android 연결 유지 서비스가 WebView와 별개로 같은 인증 세션의 소켓을 유지합니다. 홈/뒤로 가기, 다른 앱으로 전환, 채팅 화면 재생성은 연결을 종료하지 않습니다. 상태 알림의 **연결 끊기** 또는 채팅 메뉴의 **서버 연결 끊기**를 누르면 서비스와 서버 세션을 종료하고 해당 방의 푸시 구독도 해제합니다. 푸시는 서버 실행 UUID별 방에만 발송하므로 다른 서버에 연결한 기기에 섞여 전달되지 않습니다. 서버 종료/재시작은 최대 약 50초 안에 확인하며 일시적인 인터넷 단절은 재연결합니다. Android에서 앱을 강제 중지하거나 기기를 종료하면 연결은 유지할 수 없습니다.

앱을 다시 열거나 APK를 업데이트한 뒤에는 연결 유지 서비스를 재시작하고 저장된 서버 주소의 실행 UUID를 확인합니다. 이전 서버가 종료됐으면 해당 주소의 Cloudflare 오류 페이지를 열지 않고 입장 화면으로 돌아갑니다. **서버 입장**을 누르면 현재 등록된 서버 주소를 새로 찾습니다.

## 빌드 명령

SDK 경로를 Android Studio에서 설정하거나 `local.properties`에 설정한 뒤:

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

설치 가능한 개발용 APK: `app/build/outputs/apk/debug/app-debug.apk`. 스토어 배포용 서명은 별도로 필요합니다. `local.properties`, APK 출력, IDE/Gradle 캐시와 서명키는 Git에 저장하지 않습니다.

MainPC 서버를 열고 에뮬레이터/기기를 연결하면 `connectedDebugAndroidTest`로 단일 입장 버튼, 공개 주소 자동 발견, 실행 UUID 확인 및 실제 채팅 화면 로드를 검증합니다.
